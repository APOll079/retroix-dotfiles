# Desktop: how each part works

Details for `CLAUDE.md` (rules live there). Spotify drawer: `docs/spotify.md`. App / GTK theming: `docs/theming.md`. What still needs a live test: `FEATURES.md`.

## Setup
- Workspaces 1-4 are pinned to DP-2 (loop in binds.lua). DP-1 has one static workspace, 11. No workspace 10.
- SUPER+C toggles the Vesktop scratchpad (`special:spotifyspace`, name kept from when Spotify lived there). The bind launches Vesktop if it isn't running; windowrules.lua sends Vesktop there, and a Spotify started by hand still lands there hidden. Spotify is no longer launched by the bind (the Quickshell panel replaced the app); the Spicetify extension (folders / pins) only syncs while the Spotify app runs, so `library.json` goes stale until you open it once. Dropped on request, replacing the old "changes must be additive" note.
- Mouse side buttons 275/276 work with no modifier; SUPER+G toggles them for games (inputs.lua).
- F8 toggles the autoclicker: `hypr/scripts/autoclick` (fish; deploys with `hypr/`, install.sh chmods it) loops `ydotool click 0xC0` every `delay` seconds (0.05, one variable at the top) and starts `ydotoold` on its own socket if none runs. Running loops are found by the `autoclick-loop` marker in their command line (`pgrep -f`, `AUTOCLICK_TAG` swaps it for tests). Stopping lets the loop end itself (pid file removed, up to 1 s), sends a left-button release (`ydotool click 0x80`), then stops the ydotoold the script started (`autoclick-ydotoold.pid`, name checked; the same effect as `pkill -x ydotoold`, confirmed live to stop the clicking: without it clicks went on after the loop had ended). Every run is logged to `$XDG_RUNTIME_DIR/autoclick.log`; toasts go through `notify-send`. One-time root setup you run yourself: `bash scripts/autoclick-setup.sh [--dry-run]` (doas: ydotool, `/etc/udev/rules.d/80-uinput.rules`, `/etc/modules-load.d/uinput.conf`, the input group, modprobe, udev reload; skips what is done, never deletes).
- Super+S: Spotify panel (`spotify_<monitor> toggle`). Super+F1: keybind cheat sheet (`cheatsheet_<monitor> toggle`). Start menu has Services (`services_<monitor>`) and Keys; no Games button there (Games = Super+Shift+G or the launcher tab). Phone is a tab in the side panel.
- Win+D: `qs ipc call appLauncher_<focused monitor> toggleAppLauncher` (also `clipboard` on Super+V). Print and Super+Shift+S: `qs ipc call screenshot_<focused monitor> toggle` (snipping overlay; `history` opens the grid); F12 (full screen) stays instant. Super+Shift+G: Games menu (`qs ipc call games_<focused monitor> toggle`). CTRL+SHIFT+ESC opens the Task Manager (`popups/TaskManager.qml`): a real window Hyprland manages (Quickshell `FloatingWindow` titled "Task Manager"; move / resize / tile it, Super+Q closes it, the Win95 title bar drags it), one for the whole desktop (`TaskWindow.qml` singleton, `qs ipc call taskmanager open` / `performance`; the old `taskmanager_<monitor> toggle` still works). Opening it again focuses it where it is (never moved, never a second one); it is not in Bar.qml's `menus` and click-outside doesn't close it. The bind leaves real fullscreen first (`fullscreen == 2`, `hl.dsp.window.fullscreen()`; `misc.on_focus_under_fullscreen` only covers tiled windows). Rule `task-manager` (windowrules.lua, by `initial_title`): float, centre, 760x560, `min_size` 600x420, `persistent_size` (Hyprland keeps your size; the position can't be remembered, it opens centred). Sizes `MenuStyle.task*`. Also opened by the bar's CPU button (Performance tab) and SysMon popup > Task Manager...: Apps (Hyprland windows: Switch to, End task = SIGTERM to the window's pid, Kill = SIGKILL), Processes (`scripts/procs.py`, grouped by executable name, sortable, Mine/All, End/Kill for your own processes, confirm row), Performance (CPU / RAM / GPU / VRAM 60-sample bar graphs + temps). End/Kill only ever signal the picked pids; never `hl.dsp.window.close/kill` (an unknown target falls back to the active window). btop stays installed, unbound. Task Manager safety: pids must be integers > 1 and are re-read at confirm; core processes (quickshell, Hyprland, pipewire*, wireplumber, dinit*, dbus) need "End anyway"; its own helper (procs.py `self` pid) can't be ended; Enter confirms, Cancel backs out; procs.py groups interpreters by script and wine by .exe. Super+Q asks Quickshell first (`qs ipc call menus_<monitor> closeAny`, any monitor) and closes the open menu or the snipping overlay; only when none was open does it close the window (`hl.dsp.window.close()`).
- NFS: `/mnt/disk1` and `/mnt/disk2` (from the NAS) are mounted by the user service `dinit.d/nfs-mounts` (waits for `nm-online`), because boot-time fstab mounts don't wait for the network under dinit. Their fstab lines carry `noauto,user,exec` (edited by hand, outside the repo; never write /etc from a session). Confirmed live: user mounts work and the service starts; the boot timing and the NAS-off case are untested.
- easyeffects is the flatpak (`com.github.wwmm.easyeffects`), started in autostart.lua.
- `hypr/` is split into hyprland, autostart, monitors, env, look_and_feel, inputs, binds, windowrules.
- `hypr/xdph.conf` and `hypr/hyprlock.conf` hold `@HOME@` in absolute paths (no username in the repo); `bash install.sh` is the way to deploy (it fills in the real home, backs up what it overwrites, copies; it keeps an existing `quickshell/settings.json`); the user's own `~/Desktop/deploy.sh` is an alternative that fills in the home too but always overwrites `settings.json`. A `~` was tried for hyprlock's images and the lock screen looked worse (unconfirmed why), so keep absolute paths there.

## Look (rules are in the Theme section above)
- Win95 details: grippers + etched divider on the bar, title bars (inactive on toasts/OSD), dithered meter tracks, dotted focus rect on keyboard rows, bevel slider knobs (`RetroSlider`). Tried and reverted/removed: sunken wells, title-bar close boxes.
- `dusty` (themes.json) is a softer alternative to cherry (rose accent `#d4609a`; the old `#a8286a` was too dark). Since the theme manager, every app follows whichever theme is picked.
- btop squares its corners and uses the generated `current` theme (it can't group by program: its tree is parent/child only; the Task Manager does that). Window borders: focused = theme shadow, unfocused = theme outline.
- Motion: two durations and one easing (`MenuStyle.animFast` 60 ms for hover and fades, `animNormal` 120 ms for menus opening, the lyrics scroll and a cover crossfade, `animEasing` OutCubic). The toast fade-out (400) and the idle dim (1000) are slow on purpose. `settings.ui.reduceMotion` (settings.json, default false) makes every duration 0; there is no button for it in the Themes menu yet.
- Buttons (`BarButton`, `BevelButton`) use the two-ring Win95 bevel from `Bevel.qml` (outer highlight + outline, inner `MenuStyle.bevelInnerLight` + `bevelDark`) with no separate black box; pressed / toggled / checked is the same bevel sunken.
- Component gallery: `quickshell/gallery.qml` shows every shared component in every state that can be forced (hover on BarButton / BevelButton can't be, MenuRow's selected state is the same look), plus the palette and its contrast numbers. `scripts/render-gallery.sh -o OUTDIR [theme ...]` renders one PNG per theme (default: cherry dusty default) offscreen from a scratch copy: no display, a private XDG tree, `QS_NO_APPLY=1`, so it never touches the running shell. Render before and after any UI change and look at the PNGs. It is not loaded by `shell.qml`.
- Big windows: Task Manager, Games and Wallpapers have a File / View `MenuStrip` (only actions the window already has); Task Manager, Games, Wallpapers, Services and screenshot History have a bottom `StatusBar`; every list and grid scrolls with `RetroScrollBar` (content leaves `MenuStyle.scrollBarWidth` free while it shows); empty lists show an `EmptyState`; End task / Kill / Move to Trash / the session actions confirm with a `ConfirmBar`. Screenshot History is `MenuStyle.windowLargeWidth` x `windowLargeHeight` clamped to the screen; the other big windows are `windowWidth` x `windowHeight`.
- All menus on the shared components. Hover highlight works everywhere (`hoverEnabled: true` on Controls buttons). Bar menus open on click only (hover-open was built, then removed).

## Launcher (`popups/AppLauncher.qml`)
- Opens centred on the screen (frame y = screen centre minus the bar). One size for every tab and for the standalone Games menu (`MenuStyle.launcherWidth` x `launcherHeight`, 760x560). The window is a raised frame with a 24px `StartBanner` (the theme's name written up it) down the left and a `TabPage` that switches Apps / Games / Clipboard (the search box and the list sit sunken inside the page; Ctrl+Tab cycles; Super+V opens the Clipboard tab). The Games tab hosts `popups/GamesView.qml`, the same component the standalone Games menu uses (the launcher's search box feeds it and forwards arrows / Enter / Escape). Games are not mixed into app search results, and the category chip row has no Games chip (the tab replaces both; both were tried).
- Apps (fuzzy, usage-ranked, pins first when empty, category row), calculator (`utils/Calc.qml`, no eval), session actions by name (second Enter confirms), "," window search (also Super+Tab, `windows` IPC), Super+V clipboard (cliphist; Delete with an empty search or Shift+Delete removes an entry and its cached preview, a last "Clear all" row wipes after a second Enter; preview cache keeps the newest 50). Escape clears the search text, then closes. Session actions show only when the FULL action name or a whole synonym is typed (restart, logout, ...), never on a prefix ("res" shows nothing); the armed row reads "<Name> now? Enter again · Esc cancels" and disarms on cursor move, pointer leave or Escape; Lock runs on one Enter; the clipboard "Clear all" works the same; a custom action without confirm runs on one Enter only when its full name is typed. Clipboard previews decode to a .tmp then mv, delete keeps the cursor, a footer line lists the keys, the cache is capped at 50 files and 100 MB. Right-click / Shift+Enter = options (launch, pin, Move up/down, Hide / Unhide, Uninstall) in the shared `PopupMenu` (it no longer replaces the list: no Back rows; Escape or a click outside closes it and the keys return to the search box; Move up / down re-opens it on the moved app). App icons are drawn in colour as shipped (grey and tint were tried as renders and dropped: grey reads as disabled). Hidden apps leave the results and sit under a "Hidden (n)" chip; Uninstall finds the owner with `scripts/app-owner.sh` (pacman or flatpak), confirms, then runs `yay -Rns <pkg>` / `flatpak uninstall` in a kitty. State: `LauncherState.qml` in Quickshell's state dir. Hyprland binds in binds.lua call `qs ipc call appLauncher_<monitor> clipboard|toggleAppLauncher`.

## Bluetooth (`popups/BluetoothMenu.qml`)
- Native `Quickshell.Bluetooth`, no bluetoothctl anywhere (the bar button reads it too). Paired list with connect/disconnect, battery, Trust (= auto-reconnect), Forget (confirm); Available list while scanning (scan stops after 30s; click pairs, trusts, connects).
- Pairing agent: while the menu is open `scripts/bt-agent.py` (python-dbus + GLib, package `python-dbus`) runs as `org.bluez.Agent1` at `/qs/agent`, registered with `AgentManager1.RegisterAgent` as KeyboardDisplay and made the default agent (`RequestDefaultAgent`), so pairings from our menu reach it. Each BlueZ call is one JSON line on stdout; the menu shows a prompt block above the lists (title, the code or a PIN field, Pair / Allow + Cancel) and answers with one JSON line on stdin (protocol in the script's header). Kinds: PIN and passkey (type what the device shows), display PIN / passkey (type it on the device), number comparison (Pair / Cancel), authorize / service (Allow / Cancel). No answer in 60 s (`QS_BT_TIMEOUT`), Cancel, or closing the menu rejects with `org.bluez.Error.Rejected`; BlueZ's own Cancel / Release drop the prompt. `QS_BT_BUS` = a D-Bus address to use instead of the system bus (tests). Sizes `MenuStyle.bluetoothCode*`. Tested against a stub `AgentManager1` on a private bus; not against real hardware. While the menu is open the helper takes pairings that blueman's agent would otherwise get, and only then: it unregisters on stdin closing, SIGTERM and normal exit, and BlueZ drops the default by itself if the process dies (blueman is default again).

## Screenshots (`popups/ScreenshotOverlay.qml`, Super+Shift+S / Print)
- Snipping overlay (layer-shell, focused monitor): `ScreencopyView` freezes the screen, dimmed outside the highlight (`MenuStyle.shotDimOpacity`). Toolbar over the bar centre (lyrics area): Region (drag, size label; default) / Window (hover from `Hyprland.toplevels` on the active workspace, or only the shown special workspace's windows; click) / Screen / All (shoot on one click), History, X; keys 1-4, Escape. Opening it leaves open menus open, so they are in the shot. The dim and toolbar only show once the frozen frame has content (`chromeVisible`; before that the dim, which covers everything while no selection exists, could be baked into the frame: a whole-screen purple haze in every shot). To shoot it hides its chrome, waits `shotSettle`, runs grim on the frozen frame (global coords), then closes. Files go to `~/screenshots/screenshot_YYYYMMDD_HHMMSS.png`, copied, then a toast with `image-path` (thumbnail) whose click opens the image.
- History (`popups/ScreenshotPanel.qml`, Super+Shift+H or the overlay's History button, centred, `MenuStyle.windowLarge*` clamped to the screen): grid with multi-select (click, Ctrl+click, Shift+click range, Ctrl+A; arrows + dotted cursor, Shift+arrows extend), Today / Week / All quick filters or a typed date (typing resets to All), status line (count, name, size, resolution in the viewer). Viewer page (double-click / Enter / Space): 1:1 crisp when it fits, Left/Right step, Escape back. Actions on the selection: Copy (one = image, several = `text/uri-list`), Open, Delete (`gio trash`, confirm; Delete key, Enter confirms), Folder. No annotation, no delay (satty dropped by choice).
- Clipboard picker: preview pane on the left (`MenuStyle.clipPreviewFraction`), one-line list on the right. The highlighted entry (keys or hover) is decoded on demand: images with `cliphist decode` into Quickshell's cache dir (kept), text as the full entry. Inline thumbnails were tried and replaced.

## Games (`popups/GamesMenu.qml` + `popups/GamesView.qml`, Super+Shift+G; also the launcher's Games tab)
- `GamesView.qml` is the shared content (filter chips All / Recent (played in the last `MenuStyle.gamesRecentDays` days) / Steam / Other / Hidden (n), Add game, cover grid, the game's buttons); `GamesMenu.qml` is the standalone centred window around it (kept on purpose, alongside the launcher tab). Cover-art grid (7 columns, `MenuStyle.games*`). Data: `scripts/games.py` prints JSON for installed Steam games (appmanifests across library folders), Steam shortcuts (binary `shortcuts.vdf`) and the user's own entries; `GamesState.qml` runs it (on open and whenever `games.json` in Quickshell's state dir is saved) and holds the own entries (`custom`) and `hidden` ids. Steam/shortcut games launch with `steam steam://rungameid/<id>`; own entries run through `sh -c` (optional working folder). Runtimes and Proton are filtered by name. Each extra library folder gets 5 s to answer (probed with `stat` in a child process; NAS off / stale NFS) or its games come from `games-cache.json` in the state dir (covers / icons outside $HOME are probed the same way; `games.py` skips bad records and always prints a list, exit 0; GamesState has a 30 s watchdog for a hung scan; known edges: a symlink inside $HOME to a network mount is still checked in-process, a total scan failure prints [] and the list empties). A taken custom name gets " (2)".
- Keys: type to search, arrows incl. Left/Right move, Enter launches, click / Shift+Enter = the game's buttons, Escape steps back (buttons, filter), then clears the search, then closes. Add game form inside the panel (no file picker).
- Tests use a fake Steam tree in the scratch dir (`--steam-root`); never point the helper at the real Steam folder from a session. Cover lookup for shortcuts (`grid/<appid>p.png`) is unverified; missing art falls back to a letter tile.

## Cheat sheet, Services, Phone (side panel tab)
- `popups/CheatSheet.qml` (Super+F1): `scripts/binds.py` reads `hypr/binds.lua` and `hypr/inputs.lua` (next to the shell folder) and lists every `hl.bind`. Labels come from a trailing `-- help: Group | Label` comment on the bind's line; a new bind without one shows under "Other" with its dispatcher name. `for i = a, b` loops fold to "1-4"; duplicates fold ("Super+Arrows | Move focus", "Super+Shift+S / Print"), XF86 keys are named, non-UTF-8 is survived. The sheet scrolls (wheel, arrows, PageUp / PageDown) with group headings.
- `popups/ServicesPanel.qml` (Start > Services): `dinitctl --user|--system list`, filter chips, Start / Stop / Restart. A failed user-scope action shows its dinitctl error (wrapped, urgent icon) above the buttons until the next action or the next open (`actionError`; the list's own `error` is cleared by every refresh, which used to wipe it). User scope runs directly; System scope opens a floating `kitty --class qs-dialog -e doas dinitctl --system ...` (rule `qs-dialog-terminal` in windowrules.lua: float, centre, 720x420), the panel closes so the doas prompt gets the keyboard, the list refreshes when the terminal exits, a scope switch clears the old list. Parser assumes lines like `[{+}     ] name (pid: 1)`: untested against the real dinit; `parse()` is the one place to fix.
- `popups/PhoneTab.qml` (side panel, Super+N > Phone tab): KDE Connect through `kdeconnect-cli` (devices, Pair / Unpair, Ping, Send clipboard, Send file by typed path). `kdeconnectd` starts in autostart.lua. Phone notifications arrive through our notification daemon; clipboard sync is a plugin switch in the phone app. Untested without a phone.

## Screen share picker (`quickshell/sharepicker.qml`, `hypr/xdph.conf`)
- xdg-desktop-portal-hyprland runs `scripts/share-picker.sh` (xdph.conf `custom_picker_binary`, absolute path; the file is the portal's own hyprlang config, not Hyprland's Lua) whenever an app asks to share. The wrapper starts a second Quickshell (`qs -p sharepicker.qml`, `QS_NO_APPLY=1` so `Config.settingsReady()` skips apply.py) and prints `[SELECTION]<r or ->/screen:<name>` or `/window:<handle>` on stdout; printing nothing = cancelled. Input: `XDPH_WINDOW_SHARING_LIST` (`handle[HC>]class[HT>]title[HE>]mapping[HA>]`), `--allow-token` makes "Remember my choice" start checked.
- Dialog: Screens / Windows tabs, cards with a still thumbnail (`ScreencopyView`; windows are matched to Quickshell toplevels by class + title, else the app icon on an accent tile), arrows / Enter / Tab / Escape, same size as the launcher. No Region sharing (by choice: monitor or program only). The script must keep its executable bit.
- Discord asks the portal for the same share several times and XDPH starts one picker per request, so they used to stack (three Share clicks). The wrapper now runs one picker at a time (`flock`) and reuses an answer, a cancel included, for `REUSE_SECONDS` (8) after it was given; events are logged to `$XDG_RUNTIME_DIR/sharepicker/log` (`SHAREPICKER_STATE` overrides the dir for tests). A different share started within 8 s of the last one gets the old choice.
- Tested only against made-up lists and a throwaway window; the real portal handoff (environment XDPH passes, startup time) is untested live.

## Notifications
- QuickShell owns `org.freedesktop.Notifications`: mako and dunst blocked by `Exec=/bin/false` overrides in `~/.local/share/dbus-1/services/`. Spotify's track notifications are dropped.
- Toasts: 10s, title 16 px / body up to `notificationToastBodyLines` like the history, fade out (the one animation exception), left-click = the app's "default" action, right-click hides. A timed-out toast only hides; the notification stays alive in the history (`NotificationStore.qml`), so clicking the history entry still opens the app. Vesktop clicks also focus its window (reveals `special:spotifyspace`); `misc.focus_on_activate` is on. At most one toast per app: a new one replaces it; the title is the app name (+ " · n"), the summary is the first body line. Hovering a toast pauses its timeout; no toast on a monitor whose side panel Home tab is open (`NotificationStore.homeOpenOn`; it still lands in the history). `notifications.json` is mode 600 with a 7-day age cap (`historyMaxAgeDays`) and survives bad entries. Progress (`value` hint) draws a SegmentBar. Apps that offer an inline reply get a Reply button (the toast window takes the keyboard while the field is open; the timeout pauses).
- History (side panel): one entry per notification, newest first (per-app grouping was dropped: it hid all but about two rows). Each entry: icon (image or app icon), app + time ("Thu 14:05" when older than today), title Monaco 16 (`notificationTitleSize`), body Monaco 12 wrapped to `notificationBodyLines` (3) with a chevron that unfolds the rest; a click opens it in its app while it is alive, a right-click removes it without opening it (and dismisses it in the app if it is still live); live entries with an inline reply get a reply button (field under the list). The text part of the history is saved to `notifications.json` in Quickshell's state dir and restored at start (restored entries are text-only).
- DND: the "DND" button in the history header (sunken while on) or a right-click on the clock (the clock's bell turns bell-off); action buttons, position / stack limit / monitor in settings.json "notifications".

## Audio (Home tab of the side panel: `popups/AudioTab.qml` + `AudioState.qml`)
- Setup it is built around: apps -> `easyeffects_sink` -> EasyEffects 8.3.0 (flatpak, EQ) -> the FiiO DM15; the AT2020 USB mic goes through EasyEffects too (its input stays pinned); Bluetooth sometimes. Apps (Discord etc.) are never touched. EasyEffects has no command to set its output device and wires its own links, so the menu does not move streams or links. No bypass button (the bypass is automatic, below); presets are one row of buttons (below).
- **One setting you do yourself:** EasyEffects > PipeWire settings > **"Use default output" ON**. Then EasyEffects follows the system default sink by itself (its log: "New default output device"). With it off it stays pinned to its named device and the menu can't switch (the Output section then shows a hint after 3 s). Never make EasyEffects' own sink the default (its settings page warns against it); the menu only sets hardware sinks.
- Home tab, top to bottom: **Output**, **EQ preset**, **Microphone**, Applications (per-app volume; EasyEffects' own stream hidden; capped at `MenuStyle.audioAppsMaxHeight`, then it scrolls).
- **Output**: one `MenuRow` per hardware sink. A click = `Pipewire.preferredDefaultAudioSink = sink`; the tick is `Pipewire.defaultAudioSink` (EasyEffects' real target when the default isn't a hardware sink). `feeding` = the hardware sink linked from nodes of EasyEffects' own PipeWire client (same `client.id` as `easyeffects_sink`, the one name relied on); if it differs from the default for 3 s, `notFollowing` shows the hint.
- **EQ follows the output (silent)**: settings.json `audio.eqOutputMatch` (now `"DM15"`): after 1 s of no change, the sink EasyEffects really feeds decides `easyeffects -b 2` (EQ on, matching sink) or `-b 1` (bypass, any other sink, tagged "EQ off"). It also runs when a Bluetooth device connects or disconnects and once when EasyEffects (re)starts, because EasyEffects keeps the bypass state across restarts. Empty = never touched. `QS_EASYEFFECTS_CMD` replaces `flatpak run com.github.wwmm.easyeffects` in tests. Unverified: global bypass probably also bypasses the mic's EasyEffects chain (the CLI only has a global switch); if it does, set `eqOutputMatch` to `""`.
- **EQ preset**: settings.json `audio.eqPresets` (EasyEffects preset names; empty = no row): one `BevelButton` each (`MenuStyle.eqPresetColumns` per row); a click runs `easyeffects -l <name>` through the same flatpak / native / `QS_EASYEFFECTS_CMD` command as the bypass. Only a load that exits 0 becomes the sunken one, remembered in `eq-preset.json` (state dir, GuardedFileView). It never touches the automatic bypass. Tested with a fake command only.

## Wallpapers (`popups/WallpaperBrowser.qml` + `WallpaperView.qml`, `WallpaperState.qml`; Themes > Wallpapers...)
- Grid of the images in settings.json "wallpaper.folder" (default `~/Pictures/wallpapers`, top level, png/jpg/jpeg/webp), search, monitor chips (All + each output) and fit chips (cover / contain / fill / tile), Set (Enter / double-click). Sets live with `hyprctl hyprpaper wallpaper 'MON,PATH,FIT'`; the choice per monitor goes to `wallpaper.json` in the state dir and is set again at start (up to 10 tries, 1 s apart, while hyprpaper starts). hyprpaper.conf stays hands off, so its wallpaper shows briefly at boot. The lock screen follows it: every Set (and the start-up restore) also writes `~/.config/hypr/hyprlock-wallpaper.conf` (`$wallpaper_DP_2 = /path`, one per output, `#` doubled); `hyprlock.conf` has one `background` block per monitor (DP-2, DP-1) using those variables, with `wallpaper.png` as the fallback. Untested in a real hyprlock. `QS_WALLPAPER_HYPRCTL` swaps hyprctl for a fake in tests; never test against the live hyprpaper. Every monitor is tried each time (a failing one never blocks the others, ~0.3 s apart) and only the failed ones are retried (a Set 4 times, the start-up restore 30), then the status line names the monitor. Restore bug (fixed, untested live): `restore()` used to drop saved monitors missing from `Quickshell.screens` at login (commit d562c2d), so DP-2 could be skipped for good. Now it tries ALL saved monitors, retries "Invalid monitor" for `maxTries` (30 s; the hyprpaper start race), sets a screen that appears later (`onScreensChanged`), gives up quietly on unplugged ones, and logs `[wallpaper] ...` lines (`qs log | grep wallpaper`; also read-only: cat `wallpaper.json` in the state dir, `hyprctl monitors`, `hyprctl hyprpaper listloaded` / `listactive`, `pgrep -a hyprpaper`). Helper `utils/WallpaperJobs.js`. The browser puts the cursor on DP-2's picture and saved fit on open, shows an info line ("Set on DP-2 (Cover)", colour progress), has a second button "Set + theme" while the wallpaper theme is active else "Set + colours", and times out the folder listing at 10 s.
