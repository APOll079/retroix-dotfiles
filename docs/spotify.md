# Spotify drawer

Rules: `CLAUDE.md`. This is the map of how the drawer works.

- **Window**: a layer-shell `PanelWindow` drawer (Overlay layer, keyboard on demand, not exclusive), x = 0, under the bar (`margins.top: barHeight`), full height, 400 px (`spotifyWidth`), no title bar; only its right and bottom edges get a flat 1px outline. `toggleMenu` skips `anchor` for it; it has no `bar` property. `SpotifyPanel.qml` keeps the logic; the parts are `SpotifySetup`, `SpotifyHeader`, `SpotifyVolume`, `SpotifySeek`, `SpotifyButtons`, `SpotifyTransport`, `SpotifySearch`, `SpotifyPage`, `SpotifyNav`, `SpotifyHeading`, `SpotifyRecent`, `SpotifyList`, `SpotifyListHeader`, `CoverTile`, `SpotifyLyricsView`, `SpotifyStatusBar`, `SpotifyMoreMenu`, `SpotifyRowMenu`, `SpotifyTooltip`, `SpotifyHint`, `SpotifyReasonHost` (children take `required property var panel`). EVERY new type must be listed in `popups/qmldir` (an explicit list: a missing line gives "X is not a type"). Icons are `\uXXXX` escapes (the tooling turns a typed escape into a raw glyph: normalise before committing).
- **Layout, top to bottom**: header (96 px cover; title 16 px when it fits one line, else 12 bold, full title as a tooltip when cut off; artist and album that open on click; bottom row [heart][add][lyrics] ... [speaker][volume slider][percent]; while another device plays, an accent line "Playing on X · Play here" (a text link) takes the album line's place), seek (`SpotifySeek`), transport (`SpotifyButtons`: shuffle / prev / play-pause / next / repeat as five equal columns), separator, one search box, Win95 tabs Library | Liked | Queue (28 px, unselected 24) joined to the one framed page (chips or a Back row, then the list), status bar (18 px). Header arithmetic (measured): title 19.9 (Monaco 16) + artist 14.9 + album 14.9 + button row 30 = about 80 of 96; with another device playing the accent line (18 + 2) replaces the album line: about 85.
- **Sizes**: `MenuStyle.spotify*`. One button size: `spotifyButton` 30 (square icon buttons 30 x 30, text buttons and the transport columns 30 tall), glyphs `spotifyButtonGlyph` 20. Exceptions: the status bar's own buttons (Log out / Cancel confirm, "..."; 18 px bar), chips and the rows / covers toggle (flat text, `spotifyChipHeight` 20), tabs, the header's "Play here" link. No text under 12 px; Monaco only at 12 / 16. The liked heart is Spotify green (`likedColor`, the one non-palette colour, on request).
- **Click model, one path** (`panel.clickItem(index, item, moved)` for list rows, grid tiles and Recent): a song plays; an artist / album / playlist / folder opens; a container's hover play button plays it. The flick guard is a FUNCTION (`justMoved()`, `spotifyFlickGuard` 150 ms), never a binding on `Date.now()` (a binding is only re-read when `moving` changes; it stayed "just moved" after the first scroll and swallowed every click). Clicks are also ignored for `spotifyClickGuard` (350 ms) after opening something. An unknown type says "Can't open <name> (<kind>)"; a failed load keeps the opened view (name, Play) and notes "Couldn't load <name>: <reason>". Middle-click a song or its hover button: Add to queue ("Added to queue: <song>"). Right-click / Menu / Shift+F10: `SpotifyRowMenu` at the row (Play, Add to queue, Add to playlist..., Like / Remove from Liked Songs (asked: `spotify.py liked`), Go to album, Go to artist).
- **Cursor**: hidden when the drawer or a tab opens; the first arrow press only shows it, typing in the filter puts it on the first match (not the "Search Spotify for ..." row, unless nothing matches); Enter acts on it, Enter with no visible cursor does nothing; only the keyboard cursor scrolls the list (the first row brings the header back into view).
- **Library**: Spotify's Your Library via the Spicetify extension (`spicetify/Extensions/qs-folders.js` reads `LibraryAPI.getContents()` / `RootlistAPI.getContents()` every 60 s and POSTs to `spotify.py serve` on `127.0.0.1:8899` `/library` and `/folders`; Origin must be in `FOLDERS_ORIGIN_HOSTS` = xpui.app.spotify.com, unverified against the real client), else built from the API lists. Chips All / Playlists (folders in Spotify's order, Liked first; flat when the filter has text) / Albums / Artists. Pins come only from the extension: pinned items sort first under a "Pinned" heading with a plain etched line before the rest (only when both exist and the filter is empty); no badge on tiles; rows show a pin mark only when pinned and unpinned are mixed (`pinsMixed`). Rows or covers (3 per row; `grid` in `spotify-view.json`); the grid is a `ListView` of tile rows (`panel.gridRows`, Up / Down = `panel.gridMove`) so heading rows fit between groups.
- **Tiles** (`CoverTile`): square cover with a thin dark outline, caption by type (playlist "n songs" or "by owner", album = artist, folder "n playlists", artist = name only; a name without a subtitle may wrap onto two lines), a folder shows a 2 x 2 mosaic of its first four playlist covers, no art = a dim tile with the icon. Rows: 34 px, 28 px thumbnail (a speaker while it plays, title in accent), dim duration.
- **Recent**: the top of the Library list / grid's own scroll area (its header), same columns and background as the grid: the 3 newest (`spotifyRecentCount`), one row, no captions (name as hint + tooltip); its "Recent" heading (`SpotifyHeading`, the same style as "Pinned") has Hide / Show at the right end (`recentShown` in `spotify-view.json`, default open).
- **Liked / song lists**: `SpotifyListHeader` on one line (name 16 px when it fits, "n songs"; artist: discography summary) with [Play] [Shuffle]. Liked Songs opens like a folder; Back returns (`fromIndex` / `fromFilter`).
- **Queue tab**: `spotify.py queue` with no argument lists GET /me/player/queue (`{ now, items }`; with a song uri it adds). Headings "Now playing" / "Next up" over song rows; a click plays that song alone. Refreshes when the tab opens and when the track changes. A refused call (the 2026 limits may) still opens the tab: "Queue unavailable: <reason>" in the list and on the status bar. Fixture-tested only.
- **Search**: the box filters the current list; its top row "Search Spotify for 'x'" (or Enter) runs `spotify.py search` (one `/search`, `SEARCH_LIMIT` 10 per type) and shows results in place under a Back row (not a tab): dim headings, chips All / Songs / Albums / Artists / Playlists, "More songs (n)" rows, rows only. Songs play in their album; albums, artists and your own playlists open; other playlists are play-only.
- **Lyrics**: a view (header button or Ctrl+L), not a tab. Compact header ("Title · Artist", Like, Close), the lines (`lyricsFontSize` 16, `lyricsLineGap` 8 between lines, wrapped lines keep normal spacing; sung dim, current on the accent bar, coming normal; `WrapAtWordBoundaryOrAnywhere`), then volume, seek and prev / play / next rows (the same components as the main view). No empty space above the first line: the current line walks down to `lyricsAnchor` (38 %), then the view follows (no list header, only a footer). The view follows `Lyrics.index` through a Connections, not a binding; scrolling by hand pauses that for `spotifyLyricsHold`; click a line to seek. Lyrics only while this PC plays.
- **Keys** (one `panel.globalKey`, asked first by the filter box and the key catcher): Alt+Left back, Ctrl+Tab cycles the tabs, Ctrl+Left / Right previous / next, Ctrl+Shift+Left / Right seek 5 s, Ctrl+Up / Down volume 5 %, Ctrl+S like, Ctrl+L lyrics, Space play / pause while the box is empty, Left / Right seek in the lyrics. Escape: clear the box, then back, then close.
- **Volume**: while this PC plays, the slider drives the playing player's own PipeWire stream (spotifyd or the app, by `application.process.binary`); on another device, Spotify Connect volume through `spotify.py serve` (at most every `spotifyVolumeStep` ms while dragging, plus the final value). One volume stage only: spotifyd has `volume_controller = "none"`. `SpotifyState.volume` is -1 when nothing here can be driven; the slider then shows `shownVolume`, the last known level (per player, saved as `lastVolumes` in `spotify-view.json`), disabled and dimmed (`spotifyIdleOpacity`), with the reason on the status bar. The speaker is a mute toggle. With `SPOTIFY_FIXTURE` set, PipeWire is never touched (`testMode`).
- **Idle**: nothing playing anywhere = the last played song in the header (no prefix), "Last played" on the status bar, seek disabled and empty with the song's length, Play = `resume` (transfer here and carry on, else start the last song in its context).
- **Interop**: `state` says whether this PC plays (device "Desktop (spotifyd)" or the host name = the app); controls use MPRIS when local, else the API; on another device the header shows "Playing on X" + Play here (Connect transfer). spotify.py plays on the app when it is open, else on spotifyd (`spotifyd/spotifyd.conf`, dinit user service `dinit.d/spotifyd`, `--no-daemon`). `Media.isSpotify` matches both.
- **Status bar**: state / short note / error / hover hint, the confirms, the "..." menu (Reload library, Change client ID, Log out). Tooltips (`SpotifyTooltip`, after `spotifyTipMs`) only for cut-off names, Recent covers and disabled controls (`SpotifyReasonHost` says why); everything else is a status-bar hint; tooltips never cover the seek / transport rows.
- **Memory**: `spotify-view.json` (a GuardedFileView): `grid`, `recentShown`, `lastVolumes`, and `place` (tab, chip, filter, row, scroll), saved when the drawer closes as ONE object (separate writes raced with the file's own reload and lost values) and put back the first time it opens after a start (re-applied for `spotifyRestoreMs` while the list settles, because a replaced model resets the cursor).
- **Closing**: when Hyprland's active window or focused workspace changes on the drawer's own monitor (not the other one: follow_mouse), after a `spotifyClickGuard` grace period; every bar's click catcher shows while any menu is open (`MenuState.qml`).
- **Helper**: `SpotifyState.qml` runs `scripts/spotify.py` (PKCE login, tokens in the state dir `spotify/`, mode 600, never in the repo); while the drawer is open every command goes through `spotify.py serve` (JSON lines, one thread per request, kept-alive HTTPS connections from a pool of up to 4 (`POOL_MAX`), one retry on a fresh connection if a pooled one went stale); state polls every `spotifyPollMs` only while open. 2026 development-mode limits: Premium owner; track lists only for playlists you own or collaborate on (others play-only); no artist top tracks; `/search` max 10; `/artists/{id}/albums` max `limit=10` (`ARTIST_PAGE`, albums and singles fetched separately); a playlist opens with its first 500 tracks (`PLAYLIST_LIMIT`); a 429 retries once when Retry-After is at most 5 s; Recent caches names / covers for a day (`recent-cache.json`). Endpoints are listed at the top of spotify.py.
- **Tests**: offscreen renders against a made-up fixture (`SPOTIFY_FIXTURE`) only; the real login, API and the Spicetify listener are untested live.
